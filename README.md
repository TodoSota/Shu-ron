# このプログラムについて
MPMにてエネルギーを計算し、粒子の位置を更新し、その結果を3DCGとしてレンダリングするプログラム。
MPMにおけるグリッド構造を"3Dテクスチャ"にて代替し、計算、近傍へのデータ転送、描画において使用することで全体のパフォーマンス向上を図れるのではと考えている。

**ただし、コンパイルエラーこそないものの、画面内の粒子が動かないために、内部でのデータ転送や計算式に問題がある。**
**ひとまずこの現状を保存しておいて、次のブランチにおいてコードの改善に取り組む。**

# 今回での変更

# 以降の方針
正しくMPMが稼働するようにコード修正を行う。
おそらくデータ構造体(SSBOでのデータ転送)は、各種compファイルの先頭にて宣言しているstd430でなく、std140にて行われるために、正しい数値保存がなされていない可能性があるために、構造体の大規模ない改善を行う必要がある。

## MPM シミュレーションに関連するコード
### <自力追加> mpmObject.h/.cpp
1つのシミュレーション領域に必要な全リソースをパッケージ化したもの。そのためグリッドにあたる3Dテクスチャと粒子のためのvao/vboを保持している。
粒子のプロパティとグリッドのプロパティを同時に保持している。粒子のものはフィールドとして存在している。
既存のObjectと競合するため構造体の名前を変更している。

なお3Dテクスチャは、
- 補間を禁止するため GL_TEXTURE_MIN_FILTER / MAG_FILTER を GL_NEARST に設定
- 範囲外アクセス(境界端でのアクセス)時に端の値を固定するため GL_TEXTURE_WRAP_S / T / R を GL_CLAMP_EDGE に設定
している

### <自力追加>mpm_setup.comp
グリッドである3Dテクスチャの初期化。前回でのデータが残ることによりシミュレーションに影響を与えないようにする。

### <自力追加>mpm_p2g.comp
MPMにおける、P2G(Particle to Grid)の段階を担当する。細かい処理についてはコードを確認されたい。
GPUで並列計算され、その結果が4枚のテクスチャに一気に書き込まれるので、安全な書き込みのために、AtomicAddをCAS（Compare-And-Swap）ループにて実装している。

### <自力追加>mpm_grid.comp
グリッドにおける(接触判定と境界条件による)速度の更新を担当する。境界条件の処理も行うため、外部の物体との接触判定を実装したい場合はここに追加する。

### <自力追加>mpm_g2p.comp
MPMにおける、G2P(Grid to Particle)の段階を担当する。細かい処理についてはコードを確認されたい。
グリッドでの結果を戻し、それを使って一つ一つの粒子に対して各種ステータスの更新を行う。
なお通常、グリッドから粒子へ結果を戻す際には近傍粒子の探索を行わねばならないが、テクスチャであればimageLoad一つで可能となっている)
変形勾配などの値の算出が済んだ際、**塑性変形**や**硬化状態**などの材料特性の反映を行っている。

### <自力追加>mpm_move.comp
先の段階で粒子に対して返した結果を用いて、最終的な粒子位置の更新を行う。
基本的に[mpm_grid.comp]において接触判定を行うことができるが、念のため粒子単位でも粒子位置に対して境界条件の判定を行っている。

## 描画される点におけるバーテックスシェーダーとフラグメントシェーダー
### point.vert
取り出した位置をMVP行列を掛け合わせて、画面という2D上の位置に合わせて計算する。
計算している粒子と床面にて計算を変えている。床面の時のみ、シミュレーション中に傾けられるように計算を行っている。

### point.frag
描画するピクセルの色を指定しているだけ。
床と粒子で色を変えている

## 粒子ベースシミュレーションのコンピュートシェーダー
### setup.comp
シミュレーションの最初ステップにて初期化処理を行っている。
力は引き継いでいるとまずいので、こちらだけ初期化して、速度や位置などは引き継いでいる。

### update.comp
シミュレーションの中核ステップ。運動方程式を解いて力を求め、粒子を動かしている。
時間積分の計算と、簡易的な境界条件を実装している。

### collide.comp
DEMに近い計算により衝突判定を行っている。
「全対全」の総当たり探索を行っていて、O(N^2)の計算量である。
