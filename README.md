# MPM Simulation using 3D Texture Grid (OpenGL / Compute Shader)

GPU上で動作するMPM（Material Point Method）による土砂シミュレーション。  
従来のグリッド構造を**3Dテクスチャで代替**することで、データアクセスと並列処理の効率化を試みた。

## ■ 概要

MPMは粒子とグリッドを組み合わせた物理シミュレーション手法であり、

- 粒子 → 状態を保持
- グリッド → 力学計算を担当

という役割分担を持つ。

本プロジェクトでは、このグリッド構造を  
**3Dテクスチャとして実装**することで、

- データ転送の簡略化
- 近傍探索の削減
- GPU処理との親和性向上

を実現した。

---

## ■ 特徴（Features）

本システムは、MPMを用いて土砂などの粉粒体の挙動をリアルタイムに計算・可視化します。

 - **リアルタイムMPMシミュレーション**: コンピュートシェーダーによるGPUベースの実装で、高速な物理演算を実現。
 - **P2G / G2P の完全並列処理**: 粒子とグリッド間の双方向の相互作用をGPU上で効率的に処理。
 - **高度な物理モデルの導入**: 単純な弾性だけでなく、土砂の崩落や堆積を表現するための塑性変形・硬化モデルを実装。

---

## ■ パフォーマンス（Performance）

3Dテクスチャによるグリッド管理とメモリアクセスの最適化により、リアルタイム環境で以下のパフォーマンスを達成しています。

 - **約 10,000 粒子** : ~100 fps
 - **約 100,000 粒子** : ~19 fps

※ 現時点でのシステムであり、陰影計算、動的物体との当たり判定を行っていない ** 計算部分のみ ** での性能

## ■ 技術的ポイント（Technical Highlights）

本プロジェクトの最大の焦点は、従来の手法における計算コストと実装の複雑さを、GPUネイティブなアプローチで解決した点にあります。

### ● グリッドの3Dテクスチャ化
従来の配列や空間分割木を用いたグリッド構造を、**3Dテクスチャで代替**しました。

 - 空間座標をそのままインデックスとして利用し、`imageLoad` による直接アクセスを実現。
 - 近傍探索の計算処理を排除し、メモリアクセスの空間的局所性を向上。

### ● メモリアライメントの最適化
C++とGLSL間でのデータ転送におけるアライメントの不一致を防ぐため、データレイアウトを厳密に設計しています。

 - **粒子データ**: 高密度でメモリ効率の高い `std430` を採用。
 - **グリッドデータ**: 16バイト境界で安全性の高い `std140` を採用し、用途に応じた使い分けを実施。

### ● GPU実装におけるアルゴリズムの工夫

 - **競合回避**: P2Gステップにおける複数粒子からの同時書き込みを、CAS（Compare-And-Swap）ループによる安全なAtomic加算で解決。
 - **SVD（特異値分解）のGLSL実装**: 応力計算に必要なSVDを、外部ライブラリに頼らずコンピュートシェーダー内で直接実装。
