# 工程6 点検Cの整理と検証

## 工程5の本体試用

利用者はリポジトリルートから `stage5-Debug/GPUMPMTex3D.exe` を起動し、メモリ方式1、補間方式0を選択した。SSBO＋2次Bスプラインで、Sphereの打ち込み、接触を機にしたDebug Colorの変化、約70〜80 FPSを報告。ログに64³のSDF生成完了と旧Cubic表記を確認。FPSは利用者の観察値であり、GPU・計測設定・試行時間は未記録。

## 対応

| ID | 変更と判断 |
|---|---|
| C-1 | TEX/SSBOの起動ログを既存のメニューと同じ `Quadratic B-Spline` に揃えた。CSV接尾辞は既存の `QuadraticBSpline`。過去のログを保持。 |
| C-4 | 履歴は600フレームを要求上限とし、128 MiBの粒子履歴予算、GPUのSSBO単一ブロック上限、GLsizeiptrの範囲で制限。確保失敗時は候補フレーム数を半減し、1フレームも確保できなければ履歴機能を停止する。UIに容量または利用不可を表示。粒子192バイト全体と障害物スナップショットを記録。 |
| C-5 | 現行CASを維持し、最適化は延期。描画・履歴・評価・VSyncとGPUを固定し、粒子密度の異なる条件でP2G時間とCAS競合の寄与を分離して、改善が測定変動を上回ると判断できる段階で再開する。 |
| C-6 | `f_restitution`、`p_restitution`、`p_overlap`、`p_padding`、`obstacle_sphere`、`obstacle_velocity` と粒子の `scale` を予約スロットとして明記。現行シェーダーの計算では参照されない。診断バイナリと描画・評価・履歴の互換性を保つため、フィールドと初期化値を維持。CPU側に粒子192バイトとUBO112バイトのサイズ・オフセット検査を追加。 |
| C-7 | GLSLの粒子構造体、物理UBO、SVDと変形異常診断を `src/mpm/shaders/common/` に共通化。シェーダーローダーで相対パスの引用符付きincludeを展開し、コンパイル診断のsource番号とファイル名を表示する。検証ツールも同じ共通定義を読む。 |
| C-8 | 実行時参照がなかった旧move 2本を `legacy/` へ移動し、プロジェクト登録を除いた。現行の構成資料をSetup → P2G → Grid → G2Pに訂正。位置更新はG2Pで行う。 |

履歴の上限値は今回の保守判断として採用した。10,000粒子では1フレーム1,920,000バイトで、試験環境では最大69フレーム。対応する物理時間はフレームごとの成功subSteps数とdtに依存する。予算に含むのは粒子履歴バッファ。CPU側の障害物履歴や描画資源は別に確保される。

## 検証範囲

Intel UHDの実GPUで、TEX/SSBOの2次Bスプライン回帰各108判定と線形独立試験各10条件を確認。4方式のC++シミュレーターでシェーダーのロード、短い正常計算、変形異常時の保存と停止、reset復帰を検証した。

履歴プローブで10,000粒子の容量69、失敗注入時の8→4→2フレーム、上書き後の粒子全体と障害物の復元、履歴が無効な場合を確認。描画・評価の変更対象シェーダーを実ローダーでコンパイル・リンクし、故意の構文エラーに含まれるファイル名の対応付けも確認した。障害物操作や描画の全組合せは工程8。

証跡は `artifacts/baselines/` の `stage6-reg-*`、`stage6-linear-*`、`stage6-host-*`、`stage6-timeline-final/`、`stage6-final-{Debug,Release}.log`。
