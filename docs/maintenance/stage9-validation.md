# 工程9 保守性の整理と計測設計

## 作業基準と責務

開始時のHEADは `b4b851f`。工程8の実装・資料差分、未追跡のOBJと既存の試験証跡を保持した。[工程9の引継ぎ](stage9-handoff.md)と[工程8の検証記録](stage8-validation.md)を回帰基準にした。

- `SimulationSetup` が既定の物理条件、格子・粒子の上限検査、粒子初期化、物理UBO設定、履歴確保を担当する。起動と適用再起動は同じ生成経路を通る。現行設定とUIの入力値は別に保持し、候補生成成功後に現行設定、シミュレーター、履歴を更新する。
- `SimulationRun` が一時停止・コマ送り、履歴の記録・復元と再開時の分岐、通常・適用再起動を担当する。履歴と粉塵に進める時間は成功ステップに基づく。診断停止時はそのサブステップ開始前の障害物・操作状態を復元する。コンテキスト、シミュレーター、描画器などの所有はmainのローカル変数にあり、実行制御はそれらを参照する。これらのGL資源とImGuiはウィンドウより先に破棄される。
- ImGuiのウィジェットはmainから制御メソッドを呼ぶ。描画モードと描画オプションの設定はRendererの既存UIを使う。

## R-9 GPU計測の設計

現行の物理タイマーは4パスごとに1本のクエリを再利用し、成功ステップの評価処理で同期回収する。C-9はP2GとG2Pの後で同期的に診断を取得し、失敗した出力の採用を防ぐ。評価用クエリを遅延回収しても、この診断の同期は残る。描画の `PassTimer` は周回時に準備ができたフレームだけを回収する。物理CSVの全成功ステップを残す要件では、描画側と同じ欠測の扱いは使えない。

| 場面 | 遅延回収候補の仕様 |
|---|---|
| 物理ステップ | 4パスのクエリを1枠とし、成功時だけステップ番号・累積時間・dt・床設定と対応付けてFIFOに入れる。異常停止したステップのクエリは記録対象から除外する。 |
| 通常回収 | 描画フレーム境界で古い枠から準備状況を確認する。固定長の枠が満杯の場合は最古の枠を同期回収し、回数を計測する。 |
| 停止・計測切替 | 物理停止中も準備済みの結果を回収する。切替前に採取した結果は保存対象に残す。 |
| 保存・消去 | CSV保存前に未回収の枠を同期回収する。消去時は確定行と未回収行の両方を破棄する。 |
| 履歴復元・分岐 | 復元だけではログを維持する。再開時に復元ステップを超える確定行と未回収行を破棄する。 |
| 再起動・終了 | 通常再起動ではログと未回収行を破棄する。適用失敗時は現行評価器とログを保持し、成功時は旧評価器とクエリをGLコンテキストが有効な間に破棄する。 |

比較は同期版と候補版を交互に実行する。実GPUとドライバー、方式、粒子数・格子・初期状態・dt・サブステップ、描画設定、VSync、履歴、粒子評価・読み戻し、C-9の診断条件を揃える。VSyncオフでフレーム時間の中央値とp95、ステップ当たりのCPU時間、物理4パスのGPU時間、枠満杯による同期回数、保存待ち時間を記録する。既定のVSyncオンでも操作回帰を確認する。採用には同じステップ番号とメタデータを持つCSV、停止・分岐・再起動の回帰、繰り返し計測での待ち時間改善を必要とする。短時間のIntel UHD試験では、C-9読戻し後の回収直前に24件すべてが準備済みだった。今回の条件では待機削減を見込む根拠が得られなかったため、R-9は回収設計と予備確認までとし、同期回収を採用し続ける。準備状況の確認には追加のGL呼出しが入るため、計測版のCPU時間は比較していない。遅延回収の試作は、別GPUや高負荷条件で物理クエリ回収に有意な待機が観測された時点で再開する。


## 検証

| 試験 | 条件と結果 |
|---|---|
| 隔離ビルド | Visual Studio 2022 v143のDebug／Release x64で成功。PDBを共有するコンパイルがC1041で失敗したため、隔離ビルドではコンパイラに `/Z7` を追加した。プロジェクトの既定設定は維持。 |
| 統合プローブ | Intel(R) UHD Graphics、OpenGL 4.3.0、32.0.101.7082。用意されたOBJで64³のSDFを生成。Release x64の試験用コピーでUIの分岐に入力を渡し、TEX＋2次Bスプライン（1万粒子、128³）からSSBO＋線形（1000粒子、32³）への再構築、各方式でのコマ送り、4描画モード、履歴の巻き戻しと分岐、通常再起動、粒子数0の拒否、格子SSBO確保失敗注入後の再試行を確認。 |
| 工程8のCSVとの照合 | 性能・詳細は各2行。ステップ、累積時間、dt、床設定、粒子評価を照合し許容範囲内。FPSはヘッダーと行・列数を比較。GPU時間とFPSの値は実行間の数値一致の判定に含めていない。 |
| C-9の失敗注入 | SSBO＋線形で先頭粒子の変形勾配を反転させ、P2Gの診断を保存。読み出し側VBO、完了ステップ数、履歴数を維持し、試行前の障害物位置と速度へ復元。通常再起動後のコマ送りで履歴とステップが進むことを確認。 |
| 物理タイマー | 成功6ステップのCPU回収24件の直前に `GL_QUERY_RESULT_AVAILABLE` を確認し、24件とも準備済み。VSyncオン、サブステップ1、履歴と粒子評価・読み戻しを有効化し、統合プローブで4描画モードを順に切り替えた。 |

証跡は `artifacts/baselines/stage9-final-{Debug,Release}-retry.log`、`stage9-integration-run/`、`stage9-integration-extended/`（追加プローブの出力とC-9診断）。実マウス操作、長時間実行、Win32・別GPUでの試験は工程9では未実施。強いShootでの同時接触、SVD精度、描画資源確保失敗は[工程9引継ぎ](stage9-handoff.md#保留項目と再開条件)の条件で扱う。
