- 手法の比較と選定の理由は [rendering_options.md](rendering_options.md)
- 実装前の計画は [rendering_guide.md](rendering_guide.md)

にある。本書は、計画に対して **実際に何をどう実装したか**（計画から変えた点を含む）をまとめたものである。

## 1. 全体像

### 1.1 描画モード

UI の「Rendering」で、描画モードを切り替えられる。

| モード | 内容 | 主な用途 |
|---|---|---|
| Points | 従来の点描画（陰影なし） | 塑性の状態 `state` のデバッグ色の確認、比較の基準 |
| Spheres | 粒子を陰影付きの球として描く（段階 1） | 粒状の見た目 |
| Surface | 粒子の深度を平滑化して連続した面にする（段階 2） | 砂のかたまりとしての見た目 |
| Splat | 密度格子で表面粒子と法線を求め、半透明の円盤を重ねて描く | 土砂のあいまいな見た目（[splat_study.md](splat_study.md)・[splat_guide.md](splat_guide.md)） |

Splat モードは、Surface モードがスクリーン空間の処理で視点に依存し、土砂に合わないことから後で追加した。設計と実装は [splat_guide.md](splat_guide.md) にまとめてあり、この解説書では扱わない（共通の部分の変更点は §5.5 と §6.4 に記す）。

粉塵（段階 3）は、Spheres・Surface・Splat のどれでも ON / OFF できる。
デバッグ色（Space キー）は、Spheres と Surface でも球の色として使える。

### 1.2 1 フレームの処理の流れ

Spheres / Surface モードでは、`Renderer::drawScene()` が次のパスを順に実行する（軽量な deferred shading）。
パスの記号は [rendering_guide.md](rendering_guide.md) の図に対応する。

```
 シミュレーション (MpmSimulator::step × サブステップ)
        │
        ▼
 粉塵の発生と移動 (DustSystem::update)          ← シミュレーションを進めたフレームだけ
        │
 ───── 描画 (Renderer::drawScene) ──────────────────────────────────────────
        │
 (A) Shadow    光源から見た深度            粒子 (球インポスタ) + 障害物 → シャドウマップ
 (B) G-buffer  カメラから見た色・法線・深度  床 + 障害物 + 粒子 (球インポスタ)
 (D)(E) Surface  ※Surface モードのみ       粒子の深度を平滑化 → 法線を再構成 → G-buffer を書き換え
 (F) SSAO      半解像度の AO → ぼかし
 (G) Lighting  全画面で陰影を計算           太陽光 × 影 + 環境光 × AO → トーンマップ → 画面
 (H) Dust      粉塵を WBOIT で重ねる         ※粉塵 ON のとき
        │
 (I) Overlay   領域の枠線・Swing の予測軌道・ImGui (従来の処理)
```

(G) で G-buffer の深度を画面の深度バッファに書き戻すため、(I) の枠線などは、砂や障害物に正しく隠れる。

### 1.3 G-buffer の構成

| 添付 | 形式 | 内容 |
|---|---|---|
| location 0 | RGBA8 | rgb = 色（線形色空間）、a = 種別（0 = 背景、0.25 = 粒子、0.5 = 床、0.75 = 障害物） |
| location 1 | RGBA16F | ビュー空間の法線 |
| location 2 | R32F | 粒子の線形深度 $-z_{view}$ [m]（0 = 粒子なし）。Surface モードの平滑化で使う |
| 深度 | D32F | 深度バッファ（SSAO・陰影の計算・粉塵の前後判定で、位置の復元に使う） |

大きさは、ウィンドウではなく **フレームバッファの大きさ**（`Window::getFramebufferSize()`）に合わせる。
高 DPI の画面では、この 2 つの値が異なる。

## 3. 共通の基盤

### 3.1 レンダーターゲット（`RenderTarget`）

FBO と、複数のカラーテクスチャ・深度テクスチャをまとめたクラスである。
`create()` で形式を指定して作り、`resize()` で大きさが変わったときだけ同じ形式で作り直す。
深度は、後のパスでサンプリングできるように、レンダーバッファではなくテクスチャ（`GL_DEPTH_COMPONENT32F`）にしている。

### 3.2 全画面パス

`fullscreen.vert` は、頂点バッファを使わずに `gl_VertexID`（0, 1, 2）から画面を覆う三角形を作る。
空の VAO を束縛して `glDrawArrays(GL_TRIANGLES, 0, 3)` で描く。
SSAO・平滑化・陰影の計算・粉塵の合成で共通に使う。

### 3.3 GPU 時間の計測（`PassTimer`）

各パスを `GL_TIME_ELAPSED` のクエリで囲み、UI に表示する。
4 フレーム分のクエリの組を回して使い、結果は数フレーム遅れて読み出す（`GL_QUERY_RESULT_AVAILABLE` を確認し、待たない）。
表示値は指数移動平均（係数 0.1）で平滑化している。
シミュレーションのパスの時間は、従来どおり `MpmEvaluator` が計測する。

### 3.4 互換プロファイルへの対応

このプログラムの OpenGL コンテキストは互換プロファイル（GLFW の既定）である。
互換プロファイルで点スプライトの `gl_PointCoord` を使うには、`GL_POINT_SPRITE` を有効にする必要がある。
そのため、球インポスタと粉塵を描くときだけ有効にし、終わったら元に戻している（コアプロファイルでは有効にしない）。
従来の点描画で使っている `GL_POINT_SMOOTH` も、球を描く間だけ無効にする。

## 4. 段階 1: 球インポスタ・影・AO・陰影

### 4.1 描画半径

描画半径は、粒子 1 個が表す体積から決める。

$$
r_{draw} = k \cdot \frac{1}{2}\left(\frac{V_{init}}{N}\right)^{1/3}
$$

$V_{init}$ は初期立方体の体積、$N$ は粒子数、$k$ は UI の「Radius scale」（既定 1.3）である。
初期立方体の一辺は $0.2 \times$ `kWorldScale` $\times$ `particleScale` なので、`main.cpp` の `particleSpacing()` で $(V_{init}/N)^{1/3}$ を計算し、`RenderSettings::particleSpacing` に設定する。
既定の 10,000 粒子では、$(V_{init}/N)^{1/3} \approx 14$ mm、$r_{draw} \approx 9$ mm になる。
シミュレーションの `p_radius` は接触判定の閾値なので、描画には使わない。

### 4.2 球インポスタ（`sphere.vert` / `sphere.frag`）

粒子 1 個を点スプライト 1 個として描き、その中に球を描く。

**大きさ**（頂点シェーダー）: 半径 $r$ の球を投影したときの直径を、ピクセル単位で求める。

$$
\text{gl\_PointSize} = r \cdot P_{11} \cdot H / w
$$

$P_{11}$ は投影行列の `[1][1]`、$H$ は描画先の高さ、$w$ はクリップ座標の w である。
透視投影でも平行投影（$w = 1$）でも同じ式で使えるので、シャドウマップのパスでも共用できる。

**形・法線・深度**（フラグメントシェーダー）:

1. `gl_PointCoord` を $[-1, 1]^2$ に変換する（左上が原点なので y を反転）。円の外は `discard`。
2. 球面の法線（ビュー空間）を $\mathbf{n} = (c_x, c_y, \sqrt{1 - |c|^2})$ とする。
3. 球面上の点 $\mathbf{p} = \mathbf{c}_{view} + r\,\mathbf{n}$ を投影し、`gl_FragDepth` に正しい深度を書く。

深度を球面に合わせるので、粒子どうしや障害物との交差が正しくなる。
点スプライトは画面に平行な正方形なので、画面の端では輪郭がわずかに楕円になるはずだが、視野角 60° では目立たない。

**色**: 材質フラグ（粒子の `padding[0]`）で砂と石の色を選ぶ。
粒子番号の整数ハッシュで、明るさを ±`colorVariation`（既定 12%）ばらつかせ、色合いもわずかにずらす。
デバッグ色が ON のときは、`state`（0 = 引張、1 = 弾性、2 = 塑性）で色分けする。

### 4.3 床と障害物（`gbuffer_mesh.vert` / `.frag`）

- **床:** 従来の点の集まりをやめ、床の平面 $\mathbf{n}\cdot\mathbf{x} = h$ 上の大きな四角形にした。床の法線・高さは UI で変えられるので、`updateFloorQuad()` で毎フレーム頂点を作り直す。
  床は両面を描き、法線を視点の側に向ける（§9.1）。
- **障害物:** 法線を、モデルビュー行列の逆行列の転置で変換する。裏面はカリングする。

### 4.4 シャドウマップ（`ShadowMap`）

- シャドウマップ [4] を使う。光源は太陽（平行光源）で、方向は UI の方位角・仰角から求める（既定 35°, 50°）。
- シミュレーション領域 $[0, 1.5]^3$ は固定なので、領域を包む球（半径 $\frac{\sqrt{3}}{2} \times 1.5$）に合わせた平行投影を 1 枚使う。
  カメラに追従させる必要はない。
- 解像度は 2048²（UI で 1024² に変更可）。投影の幅は約 2.6 m なので 1 テクセル ≈ 1.3 mm で、粒子半径（約 9 mm）より十分細かい。
- 粒子は §4.2 と同じ球インポスタで、深度だけを書く。障害物も描く（裏面のカリングを外して、裏面も影を落とすようにする）。
- 範囲外は `GL_CLAMP_TO_BORDER`（境界の深度 1.0）で「影なし」にする。
- 参照は比較サンプラ（`sampler2DShadow`、線形補間）で 3×3 の PCF を行い、影の縁をなめらかにする。影の縁を距離に応じてさらにぼかす方法に PCSS [5] がある。
- 自己影の縞（シャドウアクネ）を防ぐため、深度のバイアス（0.0015）と、法線方向に 4 mm ずらした点で参照する処理を入れた。

### 4.5 SSAO（`SsaoPass`, `ssao.frag`, `ssao_blur.frag`）

- 半解像度で計算し、線形補間で拡大して使う。
- 法線方向の半球内の 16 サンプルが、画面上の深度で見て他の面の後ろに隠れているかを数える（Crytek 方式 [6] の半球版。より高品質な方式に HBAO [7] がある）。
- サンプル半径は描画半径の 4 倍。遠く離れた面による遮蔽は `rangeCheck` で弱める。
- サンプルの向きは 4×4 のノイズで回し、4×4 の平均で縞を消す。平均では、深度が半径以上違う画素は混ぜない（輪郭で AO がにじまないように）。
- 斜めから見た平面で自己遮蔽の縞が出たため、サンプルを接平面から離し（z ≥ 0.3）、バイアスに画素の大きさの 2 倍を加えた（§9.2）。

### 4.6 陰影の計算（`lighting.frag`）

G-buffer の深度から、逆投影でビュー座標・ワールド座標を復元して、次の式で明るさを求める。

$$
L = \rho \left[\, E_{sun}\, \mathbf{c}_{sun} \max(0, \mathbf{n}\cdot\mathbf{l})\, S \;+\; E_{amb}\, \mathrm{mix}(\mathbf{c}_{ground}, \mathbf{c}_{sky}, \tfrac{1}{2}(n_y + 1))\, A \,\right]
$$

$\rho$ は色（albedo）、$S$ は影、$A$ は AO である。
乾いた砂は粗い面なので、鏡面反射は入れていない。

その後、露出を掛けて ACES の近似 [8] でトーンマッピングし、ガンマ 2.2 で補正する。
`GL_FRAMEBUFFER_SRGB` は ImGui の色も変えてしまうので使わず、シェーダーで補正している。
背景（何も描かれていない画素）は、視線の向きによる空のグラデーションにする。
最後に `gl_FragDepth` で G-buffer の深度を画面の深度バッファに書き戻す（深度テストは `GL_ALWAYS`）。

デバッグ表示（UI の「Advanced」→「Debug view」）で、色・法線・AO・影の各成分だけを表示できる。

## 5. 段階 2: スクリーン空間で面を張る (Surface モード)

van der Laan らの screen space fluid rendering [1] の考え方を、砂に当てはめたものである。
処理は `ScreenSpaceSurface::run()` にまとめ、G-buffer の (B) と SSAO (F) の間に入る。
この後の SSAO と陰影の計算は、段階 1 と共通の処理をそのまま使う。

### 5.1 すき間を埋める球の拡大

粒子がまばら（1 セルあたり約 0.6 粒子）なため、粒子のすき間から床が見え、面に穴が開く。
そのため、Surface モードでは球を `surfaceRadiusBoost`（既定 1.4）倍に大きく描く。
G-buffer・シャドウマップ・AO の半径は、すべてこの拡大後の半径（`Renderer::drawRadius()`）を使う。

### 5.2 深度の平滑化（`smooth_depth.frag`）

G-buffer の線形深度（location 2）を、横方向 → 縦方向の 1 次元フィルタで `smoothIterations` 回（既定 2 回）平滑化する。

- **半径:** ワールド単位で決め（描画半径の 3 倍）、深度に応じてピクセル数に換算する（上限 24 px）。どの距離でも同じ粗さの面になる。
- **重み:** 距離のガウス分布。
- **範囲外のサンプルの扱い**（Truong & Yuksel の narrow-range filter [2] の考え方）:
  - 範囲より **奥** のサンプル: 捨てずに、範囲の端の深度に丸めて使う。
  - 範囲より **手前** のサンプル: 別の物体（手前の砂山）とみなして使わない。
  - 線形深度 0（粒子なし）の画素: 使わない。
- **範囲の幅:** $\text{thr}_i = \text{depthThreshold} + |i| \cdot s_{px} \cdot 5$。$s_{px}$ はこの深度で 1 画素が覆う大きさで、斜めの面ほど範囲を広くする。

奥のサンプルを捨てる通常のバイラテラルフィルタでは、斜めから見た面で縦方向の平滑化がほとんど効かず、深度が階段状に残った（§9.4・§9.5）。
丸めて使うことで、階段をならしつつ、背景に向かって面が引っ張られる量も範囲内に抑えられる。

### 5.3 法線の再構成（`normal_from_depth.frag`）

平滑化した深度から各画素のビュー座標を復元し、隣の画素との差分の外積で法線を求める。

- 左右（上下）の差分のうち、深度の差が小さいほうを使う（輪郭の向こうの面を拾わないため）。
- 深度の差が上限 $0.5\,\text{depthThreshold} + 5\,s_{px}$ を超える側は使わない。
  両側とも使えない画素（段差・孤立した粒子）では、平滑化前の球の法線を使う。
  これを入れる前は、段差の画素で下向きの法線ができ、黒い横線とちらつきの原因になっていた（§9.5）。
- **粒状感を戻す:** 平滑化すると砂粒の凹凸が消えるので、次の 2 つを加える。
  - 平滑化前の球の法線を、`sphereNormalMix`（既定 0.15）の割合で混ぜる。
  - ワールド座標の 3D 値ノイズの勾配で、法線を `grainStrength`（既定 0.3）だけ揺らす（凹凸の大きさは描画半径程度）。
    ノイズは粒子と一緒には動かない模様なので、流れている部分では模様が滑って見える場合がある。

出力は RGBA32F で、xyz = 法線、w = 平滑化した線形深度である。

### 5.4 G-buffer への書き戻し（`surface_composite.frag`）

粒子の画素だけ（w > 0）、G-buffer の法線（location 1）と深度を置き換える。
`glDrawBuffers` で location 1 だけを描画先にし、色（location 0）と線形深度（location 2）は書き換えない。
深度は、線形深度 $z$ を深度バッファの値に戻して `gl_FragDepth` に書く。

$$
d = \frac{1}{2}\left(\frac{P_{22}\,(-z) + P_{32}}{z}\right) + \frac{1}{2}
$$

### 5.5 影の参照位置の補正

平滑化した面は、シャドウマップ上の球の頂点より低くなる。
そのため、谷の部分が自分自身の影に入り、黒い斑点になった（§9.3）。
Surface モードでは、影を参照する位置を描画半径の分だけ法線方向にずらしている。

当初は `shadowNormalOffset` に加算していたため、床や障害物の画素もずれ、床に落ちる粒の影が薄くなっていた。Splat モードの追加にあわせて、`lighting.frag` に `particleShadowOffset` を設け、**粒子の画素（種別 0.25）だけ** をずらすように改めた（Surface モード: 描画半径、Splat モードで密度格子の影を使わないとき: 描画半径の 3 倍）。

### 5.6 計画からの変更点

- **厚みのパスは作っていない。** 薄い部分を透かすには、粒子の後ろにある床などの画像が別に必要で、不透明な砂では効果が小さいためである。半透明は段階 3 の粉塵で扱う。

## 6. 段階 3: 粉塵

`DustSystem` が、シミュレーションとは独立した粒子系として粉塵を扱う [3]。

### 6.1 データ

| バッファ | 内容 |
|---|---|
| 粉塵の SSBO（binding 2） | 1 個 32 バイト × 65,536 個。`posAge` = (位置, 経過時間)、`velLife` = (速度, 寿命)。寿命 0 は空き |
| カウンタの SSBO（binding 3） | リングバッファの書き込み位置（uint 1 個） |

### 6.2 発生（`dust_emit.comp`）

シミュレーションを進めたフレームに 1 回、砂の粒子バッファ（binding 0）を **読み出し専用** で走査する（1 スレッド = 砂の粒子 1 個）。

- **条件:** 速さが閾値 $v_{th}$（既定 1 m/s）を超え、かつ床からの高さが `dustNearFloor`（既定 12 cm）以内。
  重みは $\mathrm{smoothstep}(v_{th}, 2v_{th}, |\mathbf{v}_p|)$ である。
  高さの条件によって、自由落下中の砂からは出ず、着地・崩落・衝突の場所でだけ発生する。
- **確率:** `emitRate`（既定 0.06）× 重み。乱数は「粒子番号とフレーム番号の整数ハッシュ」で作るので、乱数の状態を持たずに済む。
- **書き込み位置:** `atomicAdd` でリングバッファの先頭を進める。満杯なら最も古いものを上書きする。
- **初期状態:**
  - 位置: 砂の粒子の位置から、描画半径程度ずらす。
  - 速度: $0.3\,\mathbf{v}_p$ + 床の法線方向へ $(0.15\text{〜}0.4)|\mathbf{v}_p|$ + 横方向へ $(0\text{〜}0.2)|\mathbf{v}_p|$。
  - 寿命: 平均の 0.5〜1.5 倍（既定の平均 3 秒）。

### 6.3 移動（`dust_update.comp`）

粉塵は空気に強く引きずられる細かい粒とみなし、速度を目標の速度へ指数的に近づける。

$$
\mathbf{v} \leftarrow \mathbf{v}_{target} + (\mathbf{v} - \mathbf{v}_{target})\, e^{-c_d \Delta t},\qquad
\mathbf{v}_{target} = -v_{sink}\,\hat{\mathbf{n}} + a_{turb}\, \nabla\times\boldsymbol\psi(\mathbf{x}, t)
$$

- $c_d$ は空気抵抗（既定 1.5 /s）、$v_{sink}$ は沈む速さ（既定 5 cm/s）、$\hat{\mathbf{n}}$ は床の法線である。
- 揺らぎは curl noise [9] で、周波数の違う正弦波の和をベクトルポテンシャル $\boldsymbol\psi$ とし、その回転を中心差分で求める。発散がないので、粉塵が一か所に集まったり消えたりしない。
- 床より下に入った粉塵は床の上に戻し、床へ向かう速度を消す。
- 経過時間が寿命を超えたら、空き（寿命 0）にする。
- 時間刻み Δt は、そのフレームで進めたシミュレーション時間（`timestep × subSteps`）である。一時停止中は粉塵も止まる。

### 6.4 描画（`dust.vert` / `dust.frag`）

65,536 個すべてを点スプライトとして描き、空きは頂点シェーダーで画面外へ出す。

- **大きさ:** 発生時の半径（描画半径の 6 倍）から、1 秒あたり 2 倍分ずつ広がる（上限 128 px）。
- **濃さ:** 出始めの 15% でふわっと現れ、寿命の終わりに向かって $(1 - t/T)^{1.5}$ で薄くなる。円の中はガウス分布状で、縁ほど薄い。
- **明るさ:** 粉塵 1 個につき 1 回、頂点シェーダーで、シャドウマップを参照した太陽光と空の環境光を求める。細かい粒は光をあらゆる方向へ散乱するとみなし、向きによらない明るさにする。
  - 影の判定は粉塵の中心の 1 点だけなので、砂の層の中で発生した粉塵は影と判定され、空の光だけの灰色の斑点として目立った。そこで影の効き具合 `dustShadow`（既定 0.3、0 で影なし）を加え、`lit = mix(1, lit, dustShadow)` とした。Splat モードで密度格子の影を使うときは、シャドウマップに砂を描かないので、砂による粉塵の影はなくなる。
- **前後判定と soft particle:** G-buffer の深度から面の線形深度を求める。
  - 粉塵の中心がそれより奥なら描かない。
  - 面に近いほど薄くする（描画半径の 4 倍の距離で 0 → 1）。地面や砂山に板が刺さったような境目を出さないためである。
- G-buffer の深度テクスチャをサンプリングするため、粉塵の描画先には深度バッファを付けていない。
  同じテクスチャを深度バッファとして付けたままサンプリングすると、OpenGL では動作が未定義になる（フィードバックループ）。

### 6.5 ソートなしの半透明（WBOIT）

McGuire と Bavoil の Weighted Blended OIT [10] を使う。

1. **蓄積:** 2 枚のターゲットに描く。
   - accum（RGBA16F、`glBlendFunci(0, GL_ONE, GL_ONE)`）: $\sum w\,(\alpha\mathbf{c}, \alpha)$
   - 重み $w$ は、文献の式（深度と α の関数）で、手前ほど大きくする。ただし、文献の式（係数 $10^8$、範囲 $[10^{-2}, 3\times10^3]$）を 1/100 にしている。
     合成の色は $\sum w\alpha\mathbf{c} / \sum w\alpha$ という比なので、重み全体に同じ係数を掛けても結果は変わらない。
     一方で、16 ビット浮動小数点（最大 65504）の accum があふれるまでに重ねられる粉塵の数は 100 倍（約 15,000 個）になる（§9.8）。
   - revealage（R16F、`glBlendFunci(1, GL_ZERO, GL_ONE_MINUS_SRC_COLOR)`）: $\prod (1 - \alpha)$
2. **合成**（`wboit_composite.frag`）: 平均の色 $\mathrm{accum.rgb}/\mathrm{accum.a}$ を、`glBlendFunc(GL_ONE_MINUS_SRC_ALPHA, GL_SRC_ALPHA)` で、陰影を付けた画像に不透明度 $1 - \mathrm{revealage}$ で重ねる。
   万一 accum が無限大や NaN になった画素は重ねない。

粉塵の色はトーンマップとガンマ補正の後の表示値で計算し、表示値どうしで合成している。

### 6.6 巻き戻し・再起動

粉塵の状態はタイムラインに記録していないので、巻き戻し・再起動のときは `Renderer::clearDust()` ですべて消す。

## 7. 障害物の代替形状

障害物の OBJ（`src/assets/object.obj`）は、`.gitignore`（`*.obj`）の対象でリポジトリにない。
そのため、ファイルが読めない場合は、`MeshResource::createSphere()` で半径 0.5 の UV 球（24 × 32 分割）を作って代わりに使う。
コンソールに、そのことを表示する。

- 極では面積 0 の三角形ができるので、出力しない。出力すると、SDF の内外判定で法線が NaN になり、符号を誤る。

## 9. 開発中に見つかった問題と対処

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 9.1 | 床が真っ黒になる | 床の四角形の頂点の並びが裏向きで、裏面のときに法線を反転する処理が働き、法線が下向きになっていた | 床（両面）では、法線を視線の方向で視点側へ向ける。障害物は輪郭が暗くなるのを避けるため反転しない |
| 9.2 | 平らな床に AO の横縞が出る | 斜めから見た平面では隣の画素との深度差が大きく、接平面すれすれのサンプルが自己遮蔽になる | サンプルを z ≥ 0.3 の円錐に限定し、バイアスに画素の大きさの 2 倍を加える |
| 9.3 | Surface モードで谷が黒い斑点になる | 平滑化した面がシャドウマップ上の球の頂点より低く、自分の影に入る | 影の参照位置を描画半径の分だけ法線方向へずらす |
| 9.4 | Surface モードで縦の筋が出る | 深度差の閾値が固定で、斜めから見た面の縦方向の平滑化が弾かれていた | 閾値を離れた画素数に応じて広げる。粒子のすき間は球の拡大で埋める |
| 9.5 | 低いカメラ角度で、薄い砂に黒い横線が出てちらつく | 深度が階段状に残り、段差の画素で差分から作った法線が下向きになる。粒子が動くたびに段差の位置が変わる | 平滑化を narrow-range 方式に変更し（§5.2）、法線の再構成で段差を使わない（§5.3）。連続 2 フレームで明るさが大きく変わる画素の割合が 2.40% → 1.48% に減った |
| 9.6 | 粉塵が見えない | 小さすぎ、色が床に近く、砂の面の近くで soft particle により薄くなっていた | テスト用に赤く表示して発生を確認したうえで、大きさ・濃さ・発生率・空気抵抗・色を調整 |
| 9.7 | （設計時に回避） | 粉塵の描画先に G-buffer の深度を付けたまま、その深度をサンプリングするとフィードバックループになる | 描画先に深度バッファを付けず、シェーダー内で前後判定する |

## 10. 検証の方法

開発用の環境（クラウド上の Linux）で、次の方法で確認した。

- **ビルド:** Ubuntu の GLFW・GLEW・GLM と g++ で、プロジェクト全体をビルドした。
  ファイル名の大文字小文字の違い（`Shader.h` と `shader.h` など）は、別名のリンクで吸収した。
  Visual Studio でのビルドは、ユーザーの実機で行う。
- **実行と画像の確認:** Xvfb（仮想の画面）と Mesa の llvmpipe（ソフトウェアの OpenGL 4.5）で、アプリ全体を実行した。
  ビルド用のコピーにだけ「自動で再生し、指定したフレームで画面を保存して終了する」処理を差し込んだ。
  この処理は配布するコードには入っていない。
  カメラの位置・描画モード・デバッグ表示・パラメータを環境変数で指定して、修正の前後を同じ条件で比べた。
- **OpenGL のエラー:** Debug ビルドの `Errorcheck()` を有効にして実行し、エラーが出ないことを確認した。
- **定量的な確認:** §9.5 では、同じフレームと次のフレームの画像の差から、ちらつきの量を数値で比べた。

ユーザーの実機（1280×720）での録画では、UI に表示された各パスの GPU 時間は、いずれも 0.1 ms 未満だった（Spheres / Surface モード、10,000 粒子）。

## 11. 既知の制限と今後の課題

- **側面の縦の筋:** Surface モードで、砂山の側面にわずかな縦の筋が残る。
- **画面空間の処理であること:** 面の平滑化は画面上で行うので、見る角度や砂の変形によって凹凸の出方が変わり、模様が泳ぐように見えることがある。時間方向の平滑化は入れていない。
- **薄く広がった砂:** 粒子 1〜2 個分の厚さまで薄く広がった砂は、どの面の作り方でも難しい。
  これはシミュレーション側の問題（[code_review.md](code_review.md) の A-2・A-3）によるもので、修正すると砂山が保たれ、描画の見栄えも良くなる。
- **ノイズの模様:** 細かい凹凸のノイズはワールド座標に固定されていて、粒子と一緒には動かない。
- **粉塵の見え方:** 白っぽいもやとして見え、塊としての構造は弱い。量と色は UI で調整が必要である。粉塵は砂山に影を落とさない。
- **粉塵が極端に重なる場合の精度:** accum は 16 ビット浮動小数点（有効桁は約 3 桁）なので、1 画素に数千個の粉塵が重なると、合計に対して 1 個分の寄与が丸めで消え、密集した中心に年輪のような縞が出る（発生率を既定の約 17 倍にしたテストで確認）。
  既定の設定では、Linear 補間で粉塵が出続ける状況でも、32 ビット浮動小数点の場合と見た目の差はなかった。極端に濃い粉塵が必要な場合は、accum を `GL_RGBA32F` にする（メモリと帯域は 2 倍になる）。
- **シャドウマップの範囲:** 領域を包む範囲だけを覆うので、領域の外の床には影が落ちない。
