# コード点検の結果（MPM 粒子シミュレーション）

対象は `todo-fix` ブランチ（コミット b46c479）の `src/` 以下すべてである。
重要度は次の 3 段階で表す。

- **A**: シミュレーション結果に大きく影響するもの
- **B**: 理論と一致しないが影響が限定的なもの、または特定の条件で問題になるもの
- **C**: 保守性・性能・表示に関するもの

ソースコード中の該当箇所には、`[点検]` で始まるコメントを入れてある（`grep -rn "\[点検\]" src` で一覧できる）。
**コードの動作は変えていない。** 修正するとシミュレーションの挙動とパラメータの適切な値が変わるため、修正するかどうかと、その順序は研究の方針に合わせて判断してほしい。

## 重要度 A

### A-1. SVD（Jacobi 法）の回転角の符号が逆で、分解が収束しない

- **場所**: `mpm_p2g.comp`, `mpm_p2g_Linear.comp`, `mpm_g2p.comp`, `mpm_g2p_Linear.comp` の `jacobiEigen()`
- **内容**: GLSL の行列は列優先なので、`J[p][q] = s` は (行 q, 列 p) の成分である。この置き方で $J^T S J$ の新しい非対角成分は

  $$(c^2 - s^2)\,a_{pq} + cs\,(a_{qq} - a_{pp})$$

  となり、これを 0 にする角度は $\tan 2\phi = -2a_{pq}/(a_{qq} - a_{pp})$ である。
  コードは `atan(2.0 * apq, aqq - app)` で、符号が逆になっている。
- **確認方法**: GLSL の添字の規則をそのまま NumPy で再現して、2000 個のランダムな行列で試した。

  | $\mathbf{F} = \mathbf{I} + s\,\mathcal{N}(0,1)$ | 3 反復後の非対角成分の相対残差（中央値 / 最大） | 8 反復後（最大） | 符号を直した場合（3 反復、最大） |
  |---|---|---|---|
  | $s = 0.01$ | 1.8% / 5.3% | 5.3% | — |
  | $s = 0.1$ | 17% / 40% | 41% | — |
  | $s = 0.5$ | 48% / 78% | 80% | 0.2% |

  反復を増やしても減らないので、回転が対角化として働いていない。
- **影響**: `U`, `Σ`, `V` が正しい SVD ではないため、P2G の応力と G2P の塑性判定（降伏判定・射影）の両方に誤差が入る。
  `U = F V Σ⁻¹` も直交行列にならない。
- **修正案**: `float phi = 0.5 * atan(-2.0 * apq, aqq - app);` とする（または `J[p][q]` と `J[q][p]` の `s` の符号を入れ替える）。
  4 ファイルとも同じ関数なので、`#include` が使えない GLSL では、C++ 側で共通部分を文字列として連結するなどして重複をなくすとよい。
  GPU 向けに分岐が少なく精度の高い方法として、McAdams らの 3×3 SVD [20] がある。

### A-2. G2P のアフィン行列 C が本来の Δx 倍（grid 128 で約 1/85）になっている

- **場所**: `mpm_g2p.comp`, `mpm_g2p_Linear.comp` の 2.（`new_C += 4.0 * inv_dx * weight * outerProduct(g_v, dpos)`）
- **内容**: APIC / MLS-MPM（2次 B スプライン）の正しい式は $\mathbf{C}_p = \frac{4}{\Delta x^2}\sum_i w_{ip}\mathbf{v}_i(\mathbf{x}_i - \mathbf{x}_p)^T$ である。
  コードは `dpos` をワールド単位（`* dx`）で計算したうえで、係数を `4 * inv_dx` にしている。そのため $\frac{4}{\Delta x}$ 倍となり、$\Delta x$ だけ小さい。
  Taichi の mpm88 は G2P の `dpos` を **格子単位** で計算しているので `4 * inv_dx` で正しくなる。P2G 側（ワールド単位の `dpos`）の書き方を G2P にそのまま持ち込んだと考えられる。
- **確認方法**: 線形な速度場 $\mathbf{v}(\mathbf{x}) = \mathbf{A}\mathbf{x}$ を格子に与え、コードと同じ式で $\mathbf{C}_p$ を計算した。結果は $\mathbf{C}_p = \Delta x\,\mathbf{A}$（比 0.01171875 = 1.5/128）となり、`4 * inv_dx * inv_dx` にすると $\mathbf{A}$ に一致した。
- **影響**:
  1. **変形勾配の更新** $\mathbf{F} \leftarrow (\mathbf{I} + \Delta t\,\mathbf{C})\mathbf{F}$ が本来の約 1/85 の速さでしか進まず、ひずみと応力が大幅に過小になる。実質の剛性が非常に低い状態で動いている。
  2. **APIC のアフィン運動量**（P2G の `affine * dpos`）がほとんど転送されず、PIC に近い散逸的な挙動になる（角運動量が保存されない）。
  3. 現在のヤング率と時間刻みは、この状態に合わせて調整された値である可能性が高い（B-1 を参照）。
- **修正案**: `vec3 dpos = vec3(i, j, k) - weight_dist;`（格子単位）にする。または係数を `4.0 * inv_dx * inv_dx` にする。
  修正後は、CFL 条件（B-1）に従って Δt を小さくするかサブステップを増やし、E を再調整する必要がある。

### A-3. 粒子の体積・質量が実際の配置密度と一致しない（1 セル約 0.6 粒子）

- **場所**: `main.cpp`（`mpmSimParam` の `p_vol`, `p_mass`、`resetMpmSimParam`）、`MpmSimulator::resetParticles`
- **内容**: 粒子の体積は $V_p = (\Delta x/2)^3$（1 セルに 8 粒子入る場合の値）に固定されている。
  一方、初期配置は一辺 $0.3\,s$ m の立方体（$s$ = 粒子数 / 10,000 の立方根）に一様乱数で置かれる。
  grid 128（$\Delta x = 0.0117$ m）、10,000 粒子では次のようになる。

  | 量 | 値 |
  |---|---|
  | 初期立方体の体積 | 0.027 m³ |
  | 立方体内のセル数 | 約 16,800 |
  | 1 セルあたりの粒子数 | **約 0.6**（2次 B スプラインの MPM の目安は 8 前後） |
  | $\sum_p V_p$ | 2.0 × 10⁻³ m³（実際の占有体積の約 1/13） |
  | 実効的な密度 $\sum m_p / V$ | 約 30 kg/m³（設定値は 400） |

  粒子数を変えると立方体の大きさが立方根で変わるので、この比はどの粒子数でもほぼ一定になる。
  grid 64 では 1 セルあたり約 4.8 粒子になる。
- **影響**: 粒子のない格子点が多く生じ、格子上の応力の分布が粗くなる（数値的な破断や、粒子の「すり抜け」の原因になる）。
  応力の大きさ（$V_p$ に比例）と慣性（$m_p$）の比が、物理的な値と合わない。
- **修正案**: $V_p = V_{\text{初期}} / N$、$m_p = \rho V_p$ とする。また、1 セルあたり 4〜8 粒子になるように、格子解像度か粒子数を選ぶ。
  論文で解像度を比較するときは、1 セルあたりの粒子数を明記するとよい。

## 重要度 B

### B-1. 時間刻みが弾性波の CFL 条件を満たしていない

- **場所**: `main.cpp`（`timestep = 1/1000`）
- **内容**: P 波の速さは $c = \sqrt{(\lambda + 2\mu)/\rho}$ で、E = 5×10⁴ Pa、ν = 0.3、ρ = 400 のとき $c \approx 13$ m/s になる。
  $\Delta t \le 0.3\,\Delta x / c \approx 2.7\times10^{-4}$ s となり、現在の 10⁻³ s はこの約 3.7 倍である。
  現状で発散しないのは、A-2 により実質の剛性が低いためと考えられる。
- **修正案**: A-2 を修正する場合は、Δt を $C\Delta x/(c + v_{max})$ から決めるか、サブステップの既定値を増やす。

### B-2. Kirchhoff 応力に余分な Σ が掛かっている

- **場所**: `mpm_p2g*.comp` の 3.
- **内容**: `U * stress_diag * transpose(V) * transpose(F)` は $\mathbf{U}\hat{\boldsymbol\tau}\boldsymbol\Sigma\mathbf{U}^T$ となり、正しい $\boldsymbol\tau = \mathbf{U}\hat{\boldsymbol\tau}\mathbf{U}^T$ と一致しない。
  10% の変形で相対差は約 13% になる（NumPy で確認）。コード中のコメントでも近似であると書かれている。
- **修正案**: `stress = U * stress_diag * transpose(U);` とし、`* transpose(F)` を除く。計算量も減る。

### B-3. 硬化パラメータ h3 と α の初期値が一致しない

- **場所**: `mpm_g2p*.comp` の 5.（`35.0 + (9.0 * q - 3.0) * exp(-0.2 * q)`）、`MpmSimulator::resetParticles`（`alpha = 0.267765`）
- **内容**: Klár らの値は h3 = 10（q = 0 で φ = 25°）。コードは h3 = 3（q = 0 で φ = 32°）で、初期値の α = 0.267765 は φ = 25° に相当する。
  1 ステップ目に、すべての粒子で α が 0.268 から 0.350 へ不連続に変わる。
- **修正案**: 意図に合わせて、h3 か α の初期値のどちらかに揃える。安息角を調べる実験をするなら、h0〜h3 を `MpmPhysics` に移して UI から変えられるようにするとよい。

### B-4. 線形補間で、2次 B スプライン用の D_p⁻¹ = 4/Δx² を流用している

- **場所**: `mpm_p2g_Linear.comp`, `mpm_g2p_Linear.comp`
- **内容**: 線形補間では $\mathbf{D}_p = \sum w(\mathbf{x}_i - \mathbf{x}_p)(\mathbf{x}_i - \mathbf{x}_p)^T$ が粒子位置によって変わり、定数にならない。
  そのため、MLS / APIC の係数 4/Δx² は理論的に正しくない。
  2 つの補間方式を比較する実験では、この違いが結果に混ざる点に注意が必要である。
- **修正案**: 粒子ごとに $\mathbf{D}_p$ を計算して逆行列を使う。または、線形補間では重みの勾配 $\nabla w_{ip}$ を使う通常の MPM（USL / MUSL）で力を計算する。

### B-5. 境界条件の位置が半セルずれている、領域の端に壁がない

- **場所**: `mpm_grid.comp` の 3.
- **内容**:
  - 境界判定の位置を `(coords + 0.5) * dx` としているが、P2G / G2P では格子点 i を `i * dx` に置いている。そのため床と SDF の位置が 0.5Δx ずれる。
  - 床（y = 0.1 の平面）のほかには、領域 [0, 1.5]³ の 6 面に壁の条件がない。P2G / G2P は領域外の格子点を捨てるので、端に近い粒子は運動量と質量の一部を失う。
    既存の資料（`issues_and_fixes.md` の 5.1）に書かれている「境界付近の粒子のスロッシング」の原因の候補になる。
  - 床で格子速度の法線成分を反発させている（e = 0.5）。連続体の MPM では、非弾性（法線成分を 0）とするのが普通である。
- **修正案**: `pos = vec3(coords) * dx` にする。領域の端から 2〜3 セル以内の格子点で、外向きの速度成分を 0 にする。床の反発係数は 0 を既定にする。

### B-6. SDF の扱い

- **場所**: `mpm_grid.comp`、`MeshResource::generateSDF`
- **内容**:
  1. 非等方スケール（Swing の 0.06×0.4×0.06）では、x 方向の拡大率による距離の換算が正しくない（コードのコメントにも記載あり）。
  2. 法線を uvw 空間の勾配から求めている。AABB が立方体でないと向きがずれる（各成分を軸の幅で割る必要がある）。
  3. ボクセルの値は格子点（`min + idx * cellSize`、`cellSize = 幅/(res-1)`）で計算しているが、`texture()` はテクセル中心で補間する。最大で半ボクセルずれる。
  4. 内外の判定に、最近接三角形の面法線を使っている。最近接点が辺や頂点のときに符号を誤ることがある（角度重み付き擬似法線 [21] で解決できる）。
  5. 砂から障害物への反力がない一方向の連成である（仕様として論文に明記するとよい）。

### B-7. 引張の判定で、せん断がほぼ 0 の圧縮状態も「引張」に分類している

- **場所**: `mpm_g2p*.comp` の 4.（`if (e_hat_norm < 1e-8 || tr_e > 0.0)`）
- **内容**: Klár らの場合 I は tr ε > 0 のときだけである。浮動小数点ではほぼ起こらないので、影響は小さい。

## 問題がないことを確認した点

- C++ の `MpmParticle`（192 バイト）と GLSL の `std430` 構造体、C++ の `MpmPhysics`（112 バイト）と GLSL の `std140` ブロックは、メンバのオフセットがすべて一致している。
- 2次 B スプラインの重み、`base = floor(fx - 0.5)` の取り方、P2G の力の項（$-V_p^0 \frac{4}{\Delta x^2}\boldsymbol\tau(\mathbf{x}_i - \mathbf{x}_p)$、ワールド単位の `dpos`）は、MLS-MPM の式と一致している。
- Drucker–Prager の return mapping（δγ の式、3 つの場合分け、偏差方向への射影）と α の式は、Klár らの式と一致している。体積補正も Tampubolon らの方法、および Taichi の砂の実装と同じ扱いである。
- 障害物の Coulomb 摩擦（静止摩擦と動摩擦）、剛体の点の速度 v + ω × r、Swing の速度 v = Ω × offset は正しい。
- パス間の `glMemoryBarrier` の種類は適切。ping-pong バッファの読み書きの役割、タイムラインの記録・復元の対象バッファも正しい。
- 前回修正した `writeonly` バッファの読み出し（`particleOut[idx].position.xyz +=`）は、`particleIn` から読む形で結果が同じであることを確認済み。

## 修正の優先順位の提案

1. **A-1（SVD の符号）**: 1 行の修正で、他への波及が小さい。まずこれを直して挙動を確認する。
2. **A-2（C の係数）と B-1（時間刻み）**: 同時に修正する。剛性が約 1/Δx 倍になるため、E と Δt の再調整が必要。
3. **A-3（粒子の体積と密度）**: 1 セルあたりの粒子数を 4〜8 にする。
4. B-5（境界）、B-2（応力）、B-3（硬化）。
5. 比較実験で線形補間を使うなら B-4。

それぞれの修正の前後で、`MpmEvaluator` の AABB（崩落の広がり）や最大速度、NaN の数を同じ条件で記録しておくと、修正の効果を論文の中で定量的に示せる。
