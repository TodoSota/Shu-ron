# 実装詳細（Implementation）

## ■ 3Dテクスチャによる計算グリッドの実装
本プロジェクトの核心は、MPMの格子（グリッド）を image3D として実装している点にあります。

### ● **なぜ3Dテクスチャか**
 - **O(1) の直接参照**: 空間座標を`ivec3`のインデックスとしてそのまま利用でき、近傍探索のポインタ計算やハッシュ計算を完全に排除しています。
 - **GPUネイティブ**: `imageLoad`/`imageStore`を用いることで、GPUのテクスチャユニットに最適化された形式で格子データにアクセス可能です。

### ● グリッドアクセスのロジック
P2G（粒子→格子）および G2P（格子→粒子）において、粒子周辺の $3 \times 3 \times 3$ の格子点へのアクセスは、以下のような単純なオフセットループで記述されます。

```OpenGL Shading Language
// イメージ例
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        for (int k = 0; k < 3; k++) {
            ivec3 cell_idx = base_idx + ivec3(i, j, k);
            vec4 cell_data = imageLoad(grid_texture, cell_idx);
            // ... 計算処理
        }
    }
}
```

## ■ GPUメモリレイアウトとアライメント
C++（CPU）とGLSL（GPU）間でのデータ転送における破綻を防ぐため、メモリ配置を厳密に制御しています。

### ● SSBOの構造設計
 - **粒子データ** (`std430`): 大量（数万〜数十万）の粒子を扱うため、パディングを最小限に抑えた`std430`レイアウトを採用し、メモリ帯域を最適化しています。

 - アライメント調整:`vec3`はGPU側で16バイトとして扱われるため、C++側でも`vec4`もしくは明示的なパディング変数を挿入し、データ構造の完全な一致を保証しています。

## ■ 高度な物理演算のGPU実装
MPMの複雑な数理モデルをコンピュートシェーダーで並列化するための工夫です。

### ● 競合制御：AtomicAdd (CASループ)
P2Gステップにおいて、複数の粒子が同一の格子点に同時に書き込む際の競合を避けるため`imageAtomicCompSwap`を用いた **CAS (Compare-And-Swap)** ループによる安全な加算処理を実装しています。

```OpenGL Shading Language
// AtomicAdd
// CAS ループによるAtomicAdd
void atomicAddFloatX(ivec3 coords, float val) {
    uint oldVal = imageLoad(gridIMX, coords).x;
    uint newVal, expectedVal;
    // 加算前後での値を比較、正しく書き込みが完了できるまで終わらない
    do {
        expectedVal = oldVal;
        newVal = floatBitsToUint(uintBitsToFloat(expectedVal) + val);
        oldVal = imageAtomicCompSwap(gridIMX, coords, expectedVal, newVal);
    } while (oldVal != expectedVal);
}
```

### ● SVD（特異値分解）
土砂の塑性変形を計算するための応力計算には、変形勾配のSVDが必要です。GLSL環境では外部ライブラリを使用できず、シェーダー内で**ヤコビ法を用いた固有値分解**をベースに直接実装しています。

```OpenGL Shading Language
// 特異値分解
void svd(mat3 F, out mat3 U, out mat3 Sigma, out mat3 V) {
    mat3 S = transpose(F) * F;

    jacobiEigen(S, V);  // 固有値分解

    Sigma = mat3(0.0);
  	// ゼロ除算の恐れがあるので、微小な値を足す(エプシロン)
    Sigma[0][0] = sqrt(max(S[0][0], 1e-4));
    Sigma[1][1] = sqrt(max(S[1][1], 1e-4));
    Sigma[2][2] = sqrt(max(S[2][2], 1e-4));

    mat3 invSigma = mat3(0.0);

    invSigma[0][0] = 1.0 / Sigma[0][0];
    invSigma[1][1] = 1.0 / Sigma[1][1];
    invSigma[2][2] = 1.0 / Sigma[2][2];

    U = F * V * invSigma;
}
```

## ■ SDF（符号付き距離関数）による空間・オブジェクト管理

従来の単純な「床（平面）」や「数式で定義された球」との判定から、外部の3Dモデル（OBJ）との複雑な接触判定を行うため、SDFを本格導入しました。

---

### ● SDFテクスチャの構築（CPU側）

シミュレーション開始時に、読み込んだメッシュ情報から3DテクスチャとしてSDFを事前計算します。

 - **計算アルゴリズム**: ボクセル空間の各点から、メッシュを構成するすべての三角形に対して最近接点を計算し、最短距離を求めます。
 - **内外判定**: 最近接点へのベクトルと三角形の法線の内積（ドット積）を利用し、オブジェクトの内部（負）か外部（正）かを判定します。
 - **計算コスト**: 現在は素朴な総当たり実装を行っているため、テクスチャ解像度を $R$ とした場合、計算量は $O(R^3 \times \text{ポリゴン数})$ となります。計算負荷は高いですが、初期化時の1回のみ実行し、GPUの3Dテクスチャ（GL_R32F）に転送することでランタイムの負荷をゼロにしています。
 
### ● SDFインスタンスの衝突判定と応答（GPU側）

Grid計算ステップ（mpm_grid.comp）にて、障害物との当たり判定を行います。

 - `SDFInstance`から送られた**モデル逆行列**を用いて、シミュレーション空間のワールド座標をSDFテクスチャのローカル（UVW）空間に変換してサンプリングします。
 - サンプリングされた距離が $0.0$ 未満（めり込み）の場合、SDFの勾配（法線）を計算し、ペナルティ法による押し出し力と摩擦を適用します。

## ■ インタラクションと演算のアップデート

### ● 任意形状のオブジェクト発射とレイキャスティング

マウスのクリック位置へ任意の形状（SDFインスタンス）を発射する機能を実装しました。
2Dのスクリーン座標から3D空間のベクトルを求めるため、逆行列を用いたレイキャスティングを行っています。

1. **正規化デバイス座標 (NDC)**: クリック座標を $[-1, 1]$ の範囲に変換。
2. **クリップ空間 → ビュー空間**: 投影行列の逆行列 (`invProj`) を掛け、Perspective Division（透視除算）で補正。
3. **ビュー空間 → ワールド空間**: ビュー行列の逆行列 (`invView`) を掛け、カメラ位置を起点とした方向ベクトル（Ray）を生成。

このRay方向に初速（インパルス）を与えることで、直感的なシューティングインタラクションを実現しています。

### ● エネルギー計算式の見直しとスロッシング現象

より正確な物理挙動を目指し、MPMにおけるエネルギー計算（応力・ひずみ等の更新式）の見直しを実施しました。

* **結果**: 全体的な挙動のリアリティは向上したものの、シミュレーション領域の境界（端）付近において、粒子が沸騰したように揺れ動く現象（スロッシング）が観察されるようになりました。
* **考察**: これはエネルギー保存の厳密化に伴い、境界での運動エネルギーが適切に減衰せず反射を繰り返している、あるいはSDFの境界付近の勾配計算との兼ね合いで生じているものと推測されます。今後の課題として認識しています。

## ■ まとめ

本実装では、3Dテクスチャの適用によるデータアクセスの単純化・高速化に加え、**SDFによる複雑な形状との相互作用**、および**逆行列計算を駆使した直感的なインタラクション**を実現しました。
物理演算の精緻化（エネルギー式の見直し）に伴うスロッシング現象など、新たな課題も生まれていますが、リアルタイムかつ柔軟な粉粒体シミュレーションの基盤が確立されています。
